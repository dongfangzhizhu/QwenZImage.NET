# WebUI — cross-platform manual test console

`src/QwenZImage.NET.WebUI` is an optional **ASP.NET Core Minimal API** app for
manually testing the library. It reproduces the functional surface of the
original Go WebUI (health, presets, serial job queue, cancel, retry, progress,
output gallery, trash/restore, unload, SSE) entirely in `.NET 10` — **no Go
code and no Go process**.

The browser talks to this app; the app calls `QziClient`, which
**directly P/Invokes the in-process `QwenZImageNative` shared library** via the
`qzi` C ABI. There is exactly one transport, no secondary service, no HTTP or
JSON hop between the app and the engine, and no switch to an external server.
The model pack directories come from `QwenZImage.config.json`.

It is a **test console, not the shipping SDK**. It is not packed into the
NuGet package (`IsPackable=false`); the NuGet deliverable is the managed
library plus its two platform native runtimes.

```
browser ──HTTP + SSE──▶ QwenZImage.NET.WebUI (ASP.NET Core, :7860)
                            │  QziGenerationQueue (Channels, single reader)
                            │  WebUiEngine → QziClient (LibraryImport)
                            ▼
                          QwenZImageNative.dll / libQwenZImageNative.so
                            │  qzi.c: validation · single-flight · progress
                            ▼
                          qzi_backend
                            ├─ qzi_stub.c             → noise (reference build)
                            └─ qzi_engine_backend.c   → engine/ C/CUDA (real build)
                                      ▲
                          QwenZImage.config.json (model pack paths)
```

## Run it

Prerequisites: .NET 10 SDK and a built native library (see the root README).
On Windows the library is `QwenZImageNative.dll`, on Linux
`libQwenZImageNative.so`.

```bash
# Windows (PowerShell) — reference backend, no GPU needed
.\scripts\build-native.ps1
dotnet run --project src\QwenZImage.NET.WebUI -c Release

# Linux — reference backend, no GPU needed
bash scripts/build-native-linux.sh
dotnet run --project src/QwenZImage.NET.WebUI -c Release
```

Then open <http://127.0.0.1:7860/>. For a deployable directory (contains
`wwwroot/` plus both staged native runtimes, so no `QZI_NATIVE_LIBRARY` is
needed):

```bash
dotnet publish src/QwenZImage.NET.WebUI -c Release -o artifacts/webui-publish
dotnet artifacts/webui-publish/QwenZImage.NET.WebUI.dll
```

The app falls back to its own directory for static assets when the launch
directory has no `wwwroot/`, so the published build can be started from any
working directory. User data (model weights, outputs) still resolves relative
to the launch directory.

Override the listen address with `QZI_WEBUI_URLS` or the standard `--urls` /
`ASPNETCORE_URLS` (command line always wins):

```bash
QZI_WEBUI_URLS=http://0.0.0.0:8080 dotnet run --project src/QwenZImage.NET.WebUI -c Release
```

A local `Properties/launchSettings.json` (auto-generated by some IDEs) takes
precedence over `QZI_WEBUI_URLS` and picks random dev ports. Pass
`--no-launch-profile` to ignore it, which is what CI-style smoke tests should
do.

> Binding to a non-loopback address exposes the console to your network. It is
> intended for local manual testing; there is no authentication.

## Real images: build the real native backend

The **default** native build (`QZI_WITH_CUDA_ENGINE=OFF`) links
`native/src/qzi_stub.c`, a deterministic reference backend: its `make_rgb()`
writes pseudo-random pixels and its `dit` loop only advances a progress bar.
**Matching the `steps` of the original Go version cannot fix that** — no
diffusion happens at all. The yellow banner in the UI says so explicitly, and
the health pill reads `reference backend (noise)`.

To get real images, rebuild the **same library name** with the vendored C/CUDA
engine linked in. The managed assembly, the WebUI and every API call stay
unchanged:

```bash
# Windows — script loads vcvars64 automatically; argument is the CUDA SM arch
scripts\build-native-cuda.bat 89          # RTX 4090 = 89, GB10 = 121
# Linux
bash scripts/build-native-cuda.sh 89

# Point the WebUI at the CUDA artefact and at your model packs
export QZI_NATIVE_LIBRARY=/path/to/artifacts/native/Linux-x86_64-cuda/libQwenZImageNative.so
export QZI_CONFIG=/path/to/QwenZImage.config.json
dotnet run --project src/QwenZImage.NET.WebUI -c Release
```

On Windows PowerShell:

```powershell
$env:QZI_NATIVE_LIBRARY = 'D:\...\Windows-AMD64-cuda\QwenZImageNative.dll'
$env:QZI_CONFIG = 'D:\...\QwenZImage.config.json'
dotnet run --project src\QwenZImage.NET.WebUI -c Release
```

`QwenZImage.config.json` is auto-discovered next to the app binary, in the
current directory, up to 8 parent levels above either (so the solution-root
file is found even though `dotnet run` starts the app in the project
directory), then at `~/.config/QwenZImage/config.json`; use `QZI_CONFIG` or
`--config <path>` to be explicit. Its `qwen21_dir`, `zimage_dir`,
`zimage_nunchaku_dir`, `qwen21_lora_dir` and `text_cache_dir` keys point at
model packs you supply yourself — the repository and NuGet package contain no
weights. See [ENGINE_INTEGRATION.md](ENGINE_INTEGRATION.md) for the full
configuration contract and the real backend's call chain.

`/api/health` then reports `transport: "native-pinvoke"`,
`engine.backend: "QwenZImageNative"` and `engine.reference_backend: false`;
the yellow banner disappears. Every other feature (presets, serial queue,
cancel, retry, SSE progress, gallery, trash, unload) is unchanged.

> The reference and CUDA builds produce **the same file name** into different
> `artifacts/native` subdirectories (`...-cuda` for the real one). If the UI
> still shows noise after a CUDA build, check that `QZI_NATIVE_LIBRARY` points
> at the `-cuda` artefact (or that `QZI_STAGE_CUDA=1` staged it).

### Environment variables and switches

| Variable | Default | Meaning |
| --- | --- | --- |
| `QZI_WEBUI_URLS` | `http://127.0.0.1:7860` | Kestrel listen addresses (`;`-separated) |
| `QZI_WEBUI_OUTPUT` | `<cwd>/outputs` | Gallery / trash directory |
| `QZI_CONFIG` | auto-discovered | Path to `QwenZImage.config.json`; also forwarded to the native backend |
| `--config <path>` | — | CLI equivalent of `QZI_CONFIG`, takes precedence |
| `--models <path>` | — | Override both model pack directories (`qwen21_dir` / `zimage_dir`) |
| `QZI_MODEL_DIR` | from config | `QziClientOptions.Qwen21Directory` / `ZImageDirectory` |
| `QZI_QWEN21_DIR` / `QZI_ZIMAGE_DIR` | from config | Per-model directory overrides |
| `QZI_ZIMAGE_NUNCHAKU_DIR` / `QZI_QWEN21_LORA_DIR` | from config | Pack directories for LoRA / Nunchaku weights. Read by both `QziConfig` and the native config loader; code-level `QziClientOptions` values are scoped through these variables during engine creation so the engine sees them |
| `QZI_MODEL_CACHE` | from config | Text-encoder cache directory |
| `QZI_NATIVE_LIBRARY` | auto-probe | Full path to `QwenZImageNative.dll` / `libQwenZImageNative.so` |
| `QZI_DEVICE_ID` | `-1` | CUDA device selector passed to the native backend |
| `device_id` / `thread_count` (config keys) | `-1` / `0` | Auto device / thread count; only in the config file, no env override |

`QziClient` resolves config → `QZI_*` overrides → explicit `QziClientOptions`
(most specific wins). During `qzi_engine_create()` it temporarily publishes the
chosen config path as `QZI_CONFIG` plus the directory overrides, then restores
the process environment, so both sides read the same file without leaking one
client's configuration into another. On Windows the native side reads these
values through `qzi_getenv()` rather than the CRT's stale `getenv()` snapshot;
see [ENGINE_INTEGRATION.md](ENGINE_INTEGRATION.md#作用域发布与多实例隔离).

The WebUI starts even if the native library cannot be loaded: `/api/health`
then reports `ok=false` with the exact error, and `/api/events` emits an
`event: error`. This makes it usable to diagnose a missing runtime or a bad
model path.

## HTTP API

All responses are JSON with **snake_case** field names, matching the original
Go WebUI wire format. Errors use `{"error": "...", "detail": "..."}`.

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/api/health` | WebUI + native engine status, `transport`, `config_path`, output/model dirs, uptime |
| `GET` | `/api/presets` | `{"presets":[...]}` — all `QziPresets` with a `model` discriminator |
| `POST` | `/api/jobs` | Validate + enqueue; `202` with the job snapshot |
| `GET` | `/api/jobs` | `{"jobs":[...]}` newest first; optional `?client=` filter |
| `GET` | `/api/jobs/{id}` | One job, `404` if unknown |
| `POST` | `/api/jobs/{id}/cancel` | Cancel queued job (engine never called) or signal a running one; `409` if terminal |
| `POST` | `/api/jobs/{id}/retry` | Re-submit the *same* request object; `202`, `409` if not terminal |
| `GET` / `POST` | `/api/unload` | Release re-creatable model state (native `qzi_engine_unload`) |
| `GET` | `/api/outputs` | Gallery listing, newest first |
| `GET` | `/api/outputs/{name}` | Serve one file with range support |
| `DELETE` | `/api/outputs/{name}` | Move one file into `.trash` |
| `DELETE` | `/api/outputs` | Batch delete; body `{"names":[...]}` |
| `POST` | `/api/outputs/restore` | Batch restore from `.trash`; never overwrites a newer file |
| `GET` | `/api/events` | Server-sent events: `job`, `progress`, `error`, 15 s heartbeat |
| `GET` | `/` | Static single-page console |

### Request envelope (`POST /api/jobs`)

```json
{
  "model": "qwen21",
  "prompt": "a quiet mountain lake at dawn",
  "width": 1024,
  "height": 1024,
  "seed": 42,
  "tier": "turbo",
  "client": "manual-test"
}
```

`model` accepts `qwen21` (aliases `qwen`, `qwen-image`) or `zimage`
(aliases `z-image`, `z_image`). Qwen21 adds `tier` (`turbo`/`base`);
`lora` and `lora_scale` are valid on **both** tiers, while `steps`,
`guidance` and `negative_prompt` are `base` only. The browser form keeps the
LoRA fields enabled for both tiers and sends them outside the base-only branch;
changing the adapter or its scale reloads the DiT.
Z-Image adds `checkpoint` (`bf16`, `nunchaku`, `nunchaku-r<rank>`).
The full validation rules are in [PARAMETERS.md](PARAMETERS.md); invalid
envelopes fail with `400` **before** any native model loading.

### SSE (`/api/events`)

```
retry: 3000

event: job
data: {"id":1,"state":"running","model":"zimage", ...}

event: progress
data: {"job_id":1,"phase":"Dit","completed":3,"total":8,"fraction":0.375, ...}

: ping
```

`job` events are emitted on every state transition and progress tick. While a
job is running, a matching `progress` event is emitted as well. The stream
sends a comment heartbeat every 15 seconds so proxies do not close idle
connections. `EventSource` reconnects automatically.

## Front-end features

- Model selector, presets filtered by model, prompt / negative prompt, width,
  height (step hint changes 32 ↔ 16), seed with randomiser, tier / steps /
  guidance / LoRA / checkpoint fields with automatic enable-disable rules.
  LoRA + LoRA scale stay enabled on **both** `turbo` and `base` (matching the
  library and C ABI); only steps / guidance / negative prompt are base-only.
- Live job table with state badge, progress bar, elapsed time, cancel / retry.
- Output gallery with lazy thumbnails, multi-select, batch delete, "Undo
  delete" (restore), lightbox, and direct link to the original PNG.
- Health pill showing resident model / backend (`reference backend (noise)`
  vs `QwenZImageNative`), with `transport`, `config_path` and directories in
  the tooltip, plus an "Unload model" action.
- A yellow banner whenever the noise-only reference backend is active, with
  the exact `-DQZI_WITH_CUDA_ENGINE=ON` build instruction.

## Output safety

Mirrors the Go WebUI rules in `OutputStore`:

- Names must be bare file names: no `/`, `\`, NUL, `.`, `..`, or leading `.`.
- Delete **moves** the file to `<out>/.trash` instead of unlinking it.
- Restore refuses symlinks and, if the original name has been reused, writes
  `<stem>-restored-<i><ext>` rather than overwriting the newer file.
- Only the top-level directory is enumerated; `.trash` is a subdirectory and
  therefore never appears in the gallery.

## Cross-platform notes

- The project targets `net10.0` with `Microsoft.NET.Sdk.Web` and has no
  platform-specific code of its own; the only native library is
  `QwenZImageNative`, resolved by `NativeLibraryLoader`.
- The csproj copies `artifacts/runtimes/{win-x64,linux-x64}/native/*` into
  both build and publish output. That makes the console self-contained on
  Windows and Linux; `QZI_NATIVE_LIBRARY` remains available to override it
  with a locally built CUDA artefact.
- Static assets live in `wwwroot/` and are served by `UseStaticFiles` on both
  Windows and Linux. No Node/npm build step is required.
- CI builds the solution on `ubuntu-latest` and `windows-latest` and runs a
  Linux runtime smoke test against the in-process reference backend, asserting
  `transport == "native-pinvoke"`, a resolved `config_path`, and a completed
  job whose PNG appears in the output gallery. GPU builds are not part of CI.
- On Windows, if the default port is in a system-reserved range, set
  `QZI_WEBUI_URLS` to a free port (for example
  `http://127.0.0.1:51234`).
