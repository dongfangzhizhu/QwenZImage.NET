Reference backend — not real inference. The loaded native library is the deterministic test implementation: it emits pseudo-random pixels (noise). Steps / seed / guidance only drive the progress bar — no model is loaded and no diffusion happens. To get real images you must do two things: (1) build the CUDA engine with scripts\build-native-cuda.bat / scripts/build-native-cuda.sh, and (2) select that build — building alone is not enough, because the app loads the bundled reference library by default. Set QZI_NATIVE_LIBRARY=<repo>/artifacts/native/Windows-AMD64-cuda/QwenZImageNative.dll (Linux: Linux-x86_64-cuda/libQwenZImageNative.so) and point QwenZImage.config.json at your model packs. Easiest: run scripts/start-webui-cuda.ps1 / scripts/start-webui-cuda.sh — it selects the CUDA build and refuses to serve generation jobs if the noise backend is still loaded. See docs/WEBUI.md.

ControlNet Union

Upload an already preprocessed control image (pose / canny / depth / scribble). This library does not run edge / pose / depth estimation — it consumes the control raster exactly as supplied ("raw" semantics).

Real weights required: configure the Z-Image Turbo Fun ControlNet Union weights via zimage_control_dir in QwenZImage.config.json (or QZI_ZIMAGE_CONTROL_DIR). The bundled reference backend only performs a deterministic byte comparison and emits noise — it is not real ControlNet inference.

Jobs run strictly one at a time on the native engine. This console uses no Go process, no HTTP hop to a sidecar — only the C ABI via .NET.
